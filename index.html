고급 테스트 · 측위 방식 선택
Ver 1 · 셀룰러/Wi-Fi 측위
GPS 위성 대신 기지국·Wi-Fi 신호로 위치를 잡아요. 지하에서도 대략적인 위치가 나오지만 오차가 수백 m까지 커질 수 있어서, 역 판정 반경을 넓게(600m) 잡고 "연속 확인" 횟수를 늘려 오탐을 막는 전략이에요. 브라우저에서는 저정밀 모드 요청으로 네트워크 측위를 유도합니다.
Ver 2 · 열차 실시간 운행 API
서울시 실시간 도착정보를 중계 서버를 통해 조회합니다. 열차번호·도착 상태·내리는 문 방향을 사용하며, 문 방향 값이 없으면 GPS 판단을 유지합니다.
중계 서버 연결 전 · 15초 간격으로 조회합니다
API 응답 로그가 여기에 표시돼요
Ver 3 · 타이머 추정 (Dead Reckoning)
GPS가 잘 잡히는 동안은 그대로 쓰다가, 신호가 6초 이상 끊기면 "마지막으로 확인된 위치 + 역간 평균 소요시간"으로 진행 상황을 추정해요. 도착 예상 시간이 지나면 도착으로 간주하고, 신호가 돌아오면 실측으로 즉시 보정합니다. 시뮬레이션에서 📡 버튼으로 터널 진입(신호 끊김)을 재현해보세요.

역에서 "실제로 열린 문"을 누르면 여기에 쌓여요. 이 휴대폰에서는 기록한 문이 먼저 안내되고, 복사해서 보내 주면 모든 사용자용 데이터에 반영할 수 있어요.
데이터 출처와 검증 상태
노선별 지원 범위
· 서울 1~8호선: 서울시 역사마스터 좌표로 위치를 추적합니다. 문 방향은 실시간 도착정보 API 값을 우선 쓰고, 없으면 서울교통공사 역사심도정보의 승강장 형식(섬식·상대식)과 통행 방향으로 추정합니다. 섬식(복합)·단선 역과 7호선 까치울~석남은 비워 둡니다. 1호선은 서울교통공사 구간(서울역~청량리)만 포함합니다.
· 서울 9호선: 문 방향은 실시간 API가 값을 줄 때만 표시합니다.
· 인천 1호선: 역·방면별 문 방향 베타 표를 사용합니다. 현장 검증 전입니다.
· 그 외 노선: 데이터 검증 전이라 방향을 표시하지 않습니다.

서울시 역사마스터 정보 · 서울교통공사 역사심도정보 (공공누리 제1유형) · 국가철도공단 철도데이터포털
※ 서울 1~8호선은 실시간 API 또는 승강장 구조로, 9호선은 실시간 API가 문 방향을 줄 때만, 인천 1호선은 베타 데이터로 안내합니다. 검증되지 않은 방향은 추측하지 않으며, 화살표는 추정값이므로 실제 문을 꼭 확인하세요.
