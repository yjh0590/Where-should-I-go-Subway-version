# 내리는 문 — 서울 1~9호선 자동 전환 단계

기존 밝은 UI와 CSS는 유지하고, 서울 1~9호선 역 좌표·서울시 실시간 도착정보 API·GPS 선로 교차계산·무신호 추정을 하나의 자동 추적으로 연결한 버전입니다.

## 포함된 파일

- `index.html`: 기존 화면과 위치·방향 계산, 실제 API 응답 처리
- `data/stations-seoul.js`: 서울 1~9호선 역 좌표 및 분기·순환 경로
- `data/seoul-station-master.csv`: 좌표 데이터의 원본 정리본
- `sw.js`: 화면과 역 좌표를 오프라인에 저장하되 실시간 API 응답은 캐시하지 않음. **파일을 바꿔 배포할 때마다 `CACHE` 버전을 올려야** 사용자 기기의 오래된 화면이 교체됩니다.
- `manifest.json`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`: 홈 화면 추가(PWA 설치)용 정보와 아이콘
- `config.js`: 브라우저에 공개해도 되는 Cloudflare Worker 주소만 저장
- `cloudflare-worker/`: 서울시 API 인증키를 Secret으로 숨기는 중계 서버

## 자동 추적 순서

- 서울 1~9호선의 역 좌표와 13개 운행 경로를 선택할 수 있습니다.
- Ver 2는 더 이상 모의 서버를 사용하지 않습니다.
- 중계 서버의 `/api/subway/arrivals?station=역명` 응답을 서울시 `realtimeStationArrival` 형식으로 처리합니다.
- API `subwayHeading`에 왼쪽/오른쪽 값이 있으면 해당 문 방향을 가장 먼저 사용합니다.
- API 문 방향이 없거나 오래되면 GPS 위치를 선택 노선의 선로에 투영해 현재 구간과 진행 방향을 계산합니다.
- 최근 최대 6개 GPS 위치를 교차 비교하며, 오래된 값·정확도 120m 초과·선로에서 과도하게 벗어난 값은 제외합니다.
- GPS와 유효한 API 정보가 모두 끊긴 상태에서 이미 이동 중이었다면 마지막 선로 위치·최근 속도·역간 거리를 이용해 도착 시간을 추정합니다.
- GPS가 복구되면 추정 상태를 끝내고 실제 선로 위치로 즉시 보정합니다.
- API에도 문 방향이 없으면 GPS만으로 왼쪽/오른쪽을 만들어내지 않고 `문 방향 확인 필요`를 유지합니다.
- 열차 앞쪽 보정 없이 방면별 문 열림 좌우와 역 사이 진행 방위를 조합해 문 쪽의 지리적 방위를 추정합니다.
- 절대 방위와 수평 상태가 확인될 때만 상대 화살표를 표시합니다. 기울어지거나 센서가 끊기면 화살표를 감추고 좌우 문 정보만 남깁니다.
- `359° ↔ 0°` 경계를 연속 각도로 처리하고 화면 프레임에서 시간 기반 평활화를 적용합니다. 센서 업데이트 간격이 달라도 한 바퀴 되감지 않습니다.

인증키를 브라우저 코드에 넣지 않기 위해 Cloudflare Worker 중계 서버를 사용합니다. Worker를 배포한 뒤 `config.js`에 공개 Worker 주소만 입력합니다.

```js
window.SUBWAY_API_BASE_URL = "https://naerineun-mun-api.ipasssony1234.workers.dev";
```

서울시 인증키는 `cloudflare-worker` 폴더에서 다음 명령으로 Secret에 저장합니다.

```bash
npx wrangler secret put SEOUL_API_KEY
```

실시간 API 호출은 일일 요청 제한을 고려해 15초 간격으로 조정했습니다. Worker는 동일 역 응답을 10초 동안 내부 캐시하며, 실시간 응답을 브라우저 서비스 워커에는 저장하지 않습니다.

## 데이터 출처

- 서울 열린데이터광장 `서울교통공사 역주소 및 전화번호`: 역 좌표
- 서울 열린데이터광장 `서울시 지하철 실시간 도착정보`: 열차 도착 상태와 문 방향 필드

문 방향은 API가 실제 값을 반환한 경우에만 사용하며, 현장 검증 전에는 안전 관련 확정 안내로 간주하면 안 됩니다.
