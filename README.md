# 내리는 문 — 서울 1~9호선 자동 전환 단계

기존 밝은 UI와 CSS는 유지하고, 서울 1~9호선 역 좌표·서울시 실시간 도착정보 API·GPS 선로 교차계산·무신호 추정을 하나의 자동 추적으로 연결한 버전입니다.

## 포함된 파일

- `index.html`: 기존 화면과 위치·방향 계산, 실제 API 응답 처리
- `data/stations-seoul.js`: 서울 1~9호선 역 좌표 및 분기·순환 경로
- `data/seoul-station-master.csv`: 좌표 데이터의 원본 정리본
- `data/platform-types-seoul.js`: 서울 1~8호선 역별 승강장 형식(섬식·상대식). 문 방향 추정에 사용
- `data/seoul-station-depth.csv`: 위 데이터의 원본(서울교통공사 역사심도정보, 2024-03-31 기준, UTF-8 변환본)
- `data/door-overrides.js`: 실차에서 확인한 역별 문 방향(추정값보다 우선)
- `sw.js`: 화면과 역 좌표를 오프라인에 저장하되 실시간 API 응답은 캐시하지 않음. **파일을 바꿔 배포할 때마다 `CACHE` 버전을 올려야** 사용자 기기의 오래된 화면이 교체됩니다.
- `manifest.json`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`: 홈 화면 추가(PWA 설치)용 정보와 아이콘
- `config.js`: 브라우저에 공개해도 되는 Cloudflare Worker 주소만 저장
- `cloudflare-worker/`: 서울시 API 인증키를 Secret으로 숨기는 중계 서버
- `preview.html`: PC에서 앱을 휴대폰 크기로 띄우고 나침반 센서 값을 흉내 내는 개발용 미리보기

## 화면 디자인

오른쪽 위에서 두 가지 중 고를 수 있고, 고른 값은 기기에 저장됩니다.

- `역명판`: 노선색 띠·역 이름·이전/다음 역이 있는 역명판과 남색 문 표지
- `노선도`: 한 줄의 큰 "오른쪽 문", 세로 노선도, 열린 쪽을 빨갛게 칠한 열차 평면도

## 내릴 역과 현장 기록

- 노선 아래 `내릴 역`을 고르면 중간 역에서는 "N정거장 남음"과 내릴 역의 문만 보여 주고, 내릴 역 바로 전에만 진동합니다. 역이 확인되면 내릴 역 쪽으로 방향(방면)도 정합니다. 내릴 역은 노선별로 저장됩니다.
- 위치가 잡히면 화면 아래에 "실제로 열린 문은? [왼쪽] [오른쪽]"이 나옵니다. 누른 값은 이 휴대폰에 저장되고, 그 역·방향에서는 기록한 문이 가장 먼저 안내됩니다.
- `현장 기록` 메뉴에서 기록을 복사·공유할 수 있습니다. 받은 기록은 `data/door-overrides.js`에 옮겨 적어 모든 사용자에게 반영합니다.

## 문 방향을 정하는 순서

1. 이 휴대폰에서 직접 기록한 문 → `data/door-overrides.js`의 현장 확인 값 순서로 먼저 씁니다.
2. 없으면 승강장 형식과 통행 방향으로 추정합니다. 2~8호선은 우측통행이라 섬식=왼쪽 문, 상대식=오른쪽 문이고, 1호선(서울역~청량리)은 좌측통행이라 반대입니다. 화면에 "승강장 구조로 추정한 문"이라고 표시합니다.
3. 섬식(복합)·단선 역, 7호선 까치울~석남, 9호선은 추정하지 않고 "문 방향 확인 중"으로 둡니다.
4. 인천 1호선은 별도 베타 표를 씁니다.

실시간 도착정보 API에도 `subwayHeading`(내리는 문 방향) 칸이 있지만, 2026-11-09에 12개 역 104대를 확인했을 때 전부 비어 있어 쓰지 않습니다. `?debug`의 API 로그 `door` 항목에 값이 보이기 시작하면 다시 검토합니다.

승강장 형식 데이터 출처: 서울교통공사_역사심도정보([OA-13305](https://data.seoul.go.kr/dataList/OA-13305/S/1/datasetView.do)), 공공누리 제1유형. 일부 역은 한쪽 방면만 다른 승강장을 쓰거나 양쪽 문이 열릴 수 있으므로 실차 확인이 필요합니다.

## 화면과 테스트

- 일반 화면에는 노선 선택, 큰 문 방향(`오른쪽 문`), 화살표, 시작 버튼만 보입니다.
- 주소 뒤에 `?debug`를 붙이면(`index.html?debug`) 측위 방식 테스트·시뮬레이션·API 로그가 나타납니다.
- 방위는 기기 방향(alpha·beta·gamma)을 회전행렬로 바꿔 계산하므로 휴대폰을 세워 들어도 화살표가 나옵니다. 뒤로 크게 젖힌 경우에만 화살표를 숨깁니다.
- 추적 중에는 화면 꺼짐을 막고(Wake Lock), 다음 역 도착 직전 한 번 진동합니다(왼쪽 문: 길게 1번, 오른쪽 문: 짧게 2번, 안드로이드만).

## 자동 추적 순서

- 서울 1~9호선의 역 좌표와 13개 운행 경로를 선택할 수 있습니다.
- GPS 위치를 선택 노선의 선로에 투영해 현재 구간과 진행 방향을 계산합니다. 최근 최대 6개 위치를 교차 비교하며, 오래된 값·정확도 120m 초과·선로에서 과도하게 벗어난 값은 제외합니다.
- GPS가 없으면 중계 서버의 `/api/subway/arrivals?station=역명`(서울시 `realtimeStationArrival` 형식)으로 열차 도착·출발과 방면을 받습니다. 일부 역은 API가 괄호까지 붙인 이름이나 다른 이름으로만 찾으므로 `index.html`의 `apiStationName`에서 바꿔 보냅니다.
- 둘 다 끊긴 상태에서 이미 이동 중이었다면 마지막 선로 위치·최근 속도·역간 거리로 도착 시간을 추정하고, GPS가 복구되면 실제 선로 위치로 즉시 보정합니다.
- 문 방향 정보가 없는 역에서는 GPS만으로 왼쪽/오른쪽을 만들어내지 않고 `문 방향 확인 필요`를 유지합니다.
- 열차 앞쪽 보정 없이 방면별 문 열림 좌우와 역 사이 진행 방위를 조합해 문 쪽의 지리적 방위를 추정합니다.
- 절대 방위와 수평 상태가 확인될 때만 상대 화살표를 표시합니다. 기울어지거나 센서가 끊기면 화살표를 감추고 좌우 문 정보만 남깁니다.
- `359° ↔ 0°` 경계를 연속 각도로 처리하고 화면 프레임에서 시간 기반 평활화를 적용합니다. 센서 업데이트 간격이 달라도 한 바퀴 되감지 않습니다.

인증키를 브라우저 코드에 넣지 않기 위해 Cloudflare Worker 중계 서버를 사용합니다. Worker를 배포한 뒤 `config.js`에 공개 Worker 주소만 입력합니다.

```js
window.SUBWAY_API_BASE_URL = "https://naerineun-mun-api.ipasssony1234.workers.dev";
```

서울시 인증키는 `cloudflare-worker` 폴더에서 다음 명령으로 Secret에 저장합니다.

```bash
npx wrangler secret put SEOUL_API_KEY
```

실시간 API 호출은 일일 요청 제한을 고려해 15초 간격으로 조정했습니다. Worker는 동일 역 응답을 10초 동안 내부 캐시하며, 실시간 응답을 브라우저 서비스 워커에는 저장하지 않습니다.
